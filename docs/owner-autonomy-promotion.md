# Owner autonomy promotion contract and authenticated verifier

`OWNER-AUTONOMY-PROMOTION autonomy-promotion-1` is a future owner-authenticated authorization distinct from PR review, build policy and a promotion recommendation. Required binding: repository, structural harness SHA256, activation PR number, exact activation head SHA, requested stage, L2 maximum risk, bounded daily cap, verified owner login and numeric ID, timestamp, single-use nonce and rationale. The decision must follow a qualifying evidence report and must be reverified on current GitHub APIs. New harness, head, policy, owner identity or stage invalidates the binding. A stale approval cannot authorize activation. Revocation and replay rejection are mandatory.

PR13 supplied a shape/context interface that always returned UNAVAILABLE. The 0843 implementation below adds read-only authenticated ingestion and current-object verification; deployment and exact-head owner review remain required. `validate_binding()` still reports `authenticated=false` and grants no authority by itself. Generic ledger insertion remains reserved and rejected. Runtime requires both the shared qualifying safety evidence and separate current owner authorization, so a config flip alone cannot enable autonomous starts. No token or credential belongs in an authorization payload.

Promotion preparation additionally requires autonomy to remain disabled. That reporting precondition is intentionally separate from shared read-only safety qualification, which is evaluated unchanged before and after a config flip. Runtime retains stage ordering and its stricter owner-authorization requirement. Neither report grants merge or deployment authority.


## 0843 implementation (pending owner review)

`promotion_github` reads current GitHub objects; it never creates an approval. The owner must submit a deliberate `OWNER-AUTONOMY-PROMOTION autonomy-promotion-1` comment on the activation PR through explicitly allowed connector ID 1144995 / `chatgpt-codex-connector`. The JSON contains the exact existing binding fields plus `decision=APPROVE` or `decision=REVOKE`. Use GitHub's creation timestamp (within 60 seconds), a fresh single-use nonce and rationale. Bot actors, edited comments, wrong owner/application/PR/head/harness/stage/L2/cap, stale timestamps and replay are rejected. A newer owner protocol object supersedes the older object; malformed, revoked or non-allowlisted newer objects block admission.

The operator selects the activation PR through external `DEV_AGENT_PROMOTION_PR`; this is selection only, never authority. `scripts/ingest_owner_promotion.py --pr NUMBER --ledger PRIVATE_LEDGER` records an already authenticated GitHub object. Runtime independently re-reads the current complete comment inventory, fetches the chosen object, reconstructs repository owner and PR/source/harness/config context, checks exact ingestion/nonce provenance and verifies revocation. Locally inserted JSON alone cannot satisfy current GitHub verification. `stage_control` additionally rejects generic or fixture PASS and revalidates every returned binding against independently reconstructed context.

No selection, ingestion, owner approval, activation PR, service installation or configuration change is performed by this implementation. Existing activation remains false/SHADOW. The historical interface-only paragraphs above describe PR13's deployed behavior; this implementation supersedes the unavailable adapter only after review/deployment and provisioned current owner evidence. An installed verifier without a fresh authenticated owner action still returns UNAVAILABLE. Never issue the owner's deliberate decision from an agent.
