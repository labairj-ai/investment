# Operator-controlled solo-owner protection

Human administrator installs and validates these rules; Development Agent only reads them. No rule mutation command is supplied to the coding agent.

Use two active main-targeted rulesets. The baseline has **no bypass actors** and requires PRs (zero GitHub approving reviews; no last-push approval requirement), resolved conversations, strict `test` and `owner-review` checks, no force pushes and no deletions. Bind `owner-review` to the independently operated owner-check GitHub App's integration ID. The second ruleset restricts updates; its only bypass is repository administrators (`RepositoryRole`, ID 5), **pull_request only**, and contains no other rules. The owner must be the only administrator. Keep an agent identity separate and non-admin/non-maintainer, with no bypass or ruleset-management authority. Verify behavior with the actual operational identity before acceptance.

A separate trusted controller, isolated from candidate source and agent credentials, runs `scripts/check_owner_review.py` against its private operator ledger and current PR head. Its narrowly scoped GitHub App publishes `owner-review` only for that exact head after the check succeeds. Missing attestation, changed head, revoked/deferred decision or failed CI must yield a non-success check. It must refresh/revoke checks on human decisions and head updates. App provisioning, webhook lifecycle, protected controller deployment and negative live tests remain operator acceptance work; no fake PASS is produced by this repository. Do not configure a required check until that service exists.

Ruleset templates are deliberately not submitted to GitHub. Read the current REST schemas before installation. GitHub documents [restrict updates](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets) and [PR-only bypass](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/creating-rulesets-for-a-repository). Keeping baseline and update restrictions separate prevents owner merge authority from bypassing CI or branch safety.

An owner admin credential accessible to a coding session cannot prove a non-bypass agent identity. The verifier rejects it as an operational agent, while still recognizing the owner's human merge authority. Never declare protection PASS from policy text alone.
