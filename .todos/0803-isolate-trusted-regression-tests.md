# TODO 0803 — Isolate Trusted Regression Tests from Agent-Modified Test Code

- **ID:** 0803
- **Status:** in-progress
- **Created:** 2026-10-22
- **Priority:** critical
- **Depends:** 0785, 0798
- **Blocks:** 0800, 0801

## Problem

The Development Agent currently treats `tests/*` as L1 work, which allows a candidate to modify executable pytest code that is later used to validate that same candidate.

A candidate could potentially alter `tests/conftest.py`, pytest hooks, plugin loading, collection behavior, skipping behavior or JUnit generation. This means candidate-controlled code can influence the evidence used to certify itself.

Trusted regression evidence must be generated by a test harness that the candidate cannot modify.

## Scope and acceptance

- [ ] Separate trusted regression tests from candidate-added/modified tests.
- [ ] Construct the mandatory regression-validation workspace from:
  - candidate application/source code
  - trusted test code taken from the approved base SHA
  - trusted pytest configuration taken from the approved base SHA
- [ ] Candidate-modified tests must not replace or alter trusted regression tests during mandatory certification.
- [ ] Run candidate-added tests separately as supplemental evidence.
- [ ] Explicitly protect at minimum:
  - `tests/conftest.py`
  - repository/root `conftest.py`
  - `pytest.ini`
  - pytest configuration inside `pyproject.toml`
  - pytest configuration inside `setup.cfg`
  - `sitecustomize.py`
  - `usercustomize.py`
  - pytest plugin declarations
- [ ] Treat changes to protected test-runner/configuration surfaces as at least L3 and human-started.
- [ ] Ensure mandatory regression JUnit inventory is generated exclusively from the trusted test set.
- [ ] Bind the trusted test-tree hash to the validation receipt.
- [ ] Bind the candidate source-tree hash separately.
- [ ] Store both hashes in `VALIDATION` and `VALIDATION_BATCH` evidence.
- [ ] Prevent candidate code from writing or replacing the trusted test directory inside the sandbox.
- [ ] Fail closed if base tests cannot be reconstructed exactly.

## QA requirements

- [ ] Candidate modification to `tests/conftest.py` cannot alter mandatory regression results.
- [ ] Candidate-created pytest plugin cannot influence trusted regression collection.
- [ ] Candidate test calling `pytest.skip()` globally cannot hide trusted tests.
- [ ] Candidate test rewriting JUnit output cannot satisfy mandatory validation.
- [ ] Candidate may still add legitimate new tests and receive supplemental test evidence.
- [ ] Trusted regression inventory remains identical to approved-base inventory except where expected application behavior changes produce legitimate result changes.
- [ ] Full development-agent adversarial suite passes.
- [ ] Full repository suite passes.

## Implementation guardrails

- Do not simply ban all new tests.
- Do not trust test counts reported by candidate code.
- Do not let the Builder modify the trusted test oracle.
- Candidate-written tests supplement validation; they do not define validation success.
