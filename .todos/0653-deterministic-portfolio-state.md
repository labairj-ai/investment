# Make portfolio_state Fully Deterministic

- **ID:** 0653
- **Status:** done
- **Created:** 2026-09-24
- **Priority:** high
- **Depends:** 0650, 0651

## Problem

`portfolio_state` is currently generated by the LLM and then repaired by `_apply_brief_policy()`. This creates two problems:

1. **Floor but no ceiling:** the policy enforces a minimum (attention → ATTENTION, high-severity → URGENT) but not a maximum. A healthy portfolio with no attention items can receive URGENT from the LLM and the policy allows it. The LLM can contradict the deterministic definition in the direction of over-escalation.

2. **Normalization order bug:** normalization (`"GARBAGE" → UNKNOWN`) currently runs *after* the severity floor. With a medium-severity attention item and an invalid LLM state, the flow is: `"GARBAGE"` is not `STABLE` or `UNKNOWN` → severity floor skips it → normalization → `UNKNOWN`. Final result is UNKNOWN, but the semantic says any attention item must be at least ATTENTION. Fix: normalize first, then apply floors.

The complete deterministic definition now exists:
- high-severity attention (severity ≥ 70) → URGENT
- any other attention → ATTENTION
- no attention + REQUIRED sources unhealthy → UNKNOWN
- no attention + REQUIRED sources healthy → STABLE

There is no remaining reason to ask the LLM to decide this. Asking a probabilistic model to generate a value and then correcting it costs policy complexity and allows over-escalation.

## Proposed approach

- **Derive `portfolio_state` entirely from `brief_state`** in `_apply_brief_policy()`. Do not read `portfolio_state` from the LLM output at all for the authoritative field.
- **Fix normalization order:** normalize any incoming `portfolio_state` from LLM to one of the four valid values first, then apply the deterministic floors. This eliminates the medium-severity + invalid-state edge case.
- **Optional diagnostic field:** if there is value in retaining the model's assessment for debugging, store it as `llm_assessed_state` (not rendered in UI, not used for policy). Otherwise omit.
- **LLM output schema:** the briefing prompt should no longer ask for `portfolio_state`. The LLM produces only `headline`, `what_changed`, `key_question`. Remove the field from the prompt schema and the expected output parser.
- **No behavioral change for users:** the displayed state was already being overridden in most cases. This removes the LLM from the path entirely.

## Touches

- `portfolio_ai.py` — `_apply_brief_policy()`: fix normalization order; derive `portfolio_state` from `brief_state` directly; LLM output `portfolio_state` stored as `llm_assessed_state` or discarded
- `agents/briefing_agent.py` — remove `portfolio_state` from LLM prompt schema and output parser; add `llm_assessed_state` passthrough if retained
- `tests/` — test: invalid LLM state + medium attention → ATTENTION (not UNKNOWN); test: LLM returns URGENT + no attention + healthy → STABLE (ceiling enforced); test: high-severity + any LLM state → URGENT
